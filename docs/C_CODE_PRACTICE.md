# C 실행 결과 예측 문제은행

## 구성

- 하 50문항: 기본 연산, 반복·분기, 배열, 문자열, 값/주소 전달, 포인터, 단일 재귀, unsigned 비트 연산.
- 중 50문항: 정렬 중간 상태, 분기 재귀, static 지역 변수, 행 포인터, 문자열 변경, 구조체 복사, 이중 포인터, 원형 큐, 이진 탐색.
- 상 50문항: 트리 순회와 갱신, 리스트 삭제·역순·가중합, 재귀와 공유 static 상태/콜백, 행 포인터 재배열과 재귀, 문자열 별칭/재귀 교환, 원형 큐 명령과 재삽입, 구조체 얕은 복사/콜백, 후위식 스택/공유 상태, 백트래킹/복원, 포인터 반환/함수 테이블.

각 난이도는 10개 유형을 5개씩 변형한 구조입니다. 서로 다른 유형 150개라는 의미가 아니며, 같은 개념을 데이터·조건·호출 순서 등의 변형으로 반복 연습하도록 구성했습니다. 상은 여러 개념을 결합해 일반 기출보다 길고 복잡하게 확장한 킬러 연습 문제입니다. 실제 시험의 난이도를 보장하는 분류는 아닙니다.

문제, 정답 출력, 개념 해설, 구체적인 단계별 추적을 함께 제공합니다. 원문 복제가 아닌 기출 개념 기반 창작 문제이며 특정 회차의 실제 문제인 것처럼 표기하지 않습니다. C11 기준의 정의된 동작만 사용하며 플랫폼에 따라 값이 달라지는 주소 출력·sizeof(int)·signed char 가정이나 평가 순서가 정해지지 않은 증감 조합은 사용하지 않습니다.

## 화면과 기록

`코드 연습 → C → 하/중/상`에서 선택하거나 같은 난이도의 랜덤 문제를 엽니다. 모달에 출력 결과를 입력하고 채점하면 정답과 해설이 공개됩니다. 공백/줄바꿈의 양만 정규화하고 값의 순서, 대소문자, 기호는 유지합니다. `1 23`과 `12 3`을 같은 답으로 처리하지 않습니다.

로그인 사용자의 `practice_attempts`에 `practice_type: C`, 문제 ID와 정오답을 저장합니다. 제출 중에는 중복 제출을 막고 저장 실패를 알립니다. 저장 재시도는 같은 UUID를 사용해 같은 풀이의 중복 기록을 방지합니다. 기존 C 통계가 해당 기록을 집계합니다. Java/Python 문제 생성은 이번 작업에 포함하지 않았습니다.

## 검증 재실행

```powershell
npm run verify:c -- <zig.exe의 경로>
```

검증 스크립트는 각 난이도 50개, ID/소스 중복 없음, 해설과 추적 존재, 출력 채점 경계값을 검사합니다. 사용자 정의 식별자를 문제별로 분리한 C 검증 프로그램을 만들어 C11·경고 오류 처리로 컴파일하고, `-O0`/`-O2` 모두에서 150개 출력이 정답과 일치하는지 확인합니다. Zig 0.15.2로 검증했습니다. 정적 식별자 분리 작업은 문자열 리터럴을 변경하지 않습니다.

컴파일러와 생성된 검증 C/실행 파일은 Git에서 제외된 `node_modules/.cache/c-verifier`에만 위치합니다. 웹에서는 사용자 입력 코드를 실행하지 않으며 배포 서버에 C 컴파일러가 필요하지 않습니다.

로컬 격리 브라우저 화면에서 난이도별 50개 카드, 공백/줄바꿈 정답 채점, 오답 해설, 다음 랜덤 문제, 모달 답안 초기화, Escape 닫기, 언어 전환과 저장 실패/재시도를 확인했습니다. 이 검증은 인증과 저장을 모의 객체로 대체하여 실제 사용자 데이터에 기록을 만들지 않았습니다. 실제 Supabase 저장의 종단 간 검증은 로그인 세션이 없어 수행하지 않았습니다. React 검토에서는 모달의 키보드 포커스 처리와 상태 초기화, 중복 제출 방지, 저장 예외 처리를 확인했습니다.
