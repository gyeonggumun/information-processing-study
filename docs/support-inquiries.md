# 문의하기와 관리자 문의 관리

## 이용 방법

- 로그인 후 닉네임 메뉴 또는 하단의 `문의하기`로 이동합니다. User·Pro·Admin 모두 문의를 작성할 수 있습니다.
- 유형(일반/학습 자료/오류/계정), 제목 2~120자, 내용 10~5,000자로 접수합니다. 비밀번호·인증번호 등 민감한 정보는 적지 않도록 안내합니다.
- `내 문의`에서 본인의 문의와 관리자 답변만 볼 수 있습니다. 상태별 필터와 10개 단위 이전/다음 이동, 새로고침을 제공합니다.
- 관리 페이지의 `계정 관리 / 문의 관리` 탭에서 문의 관리로 이동합니다. Admin만 전체 문의와 작성자 정보(기존 이메일·닉네임)를 확인하고 답변·상태를 저장할 수 있습니다.
- 상태는 `접수 대기 → 확인 중 → 답변 완료`입니다. 내용이 있는 답변은 답변 완료로 저장하며, 답변 없이 접수 대기/확인 중으로 저장할 수도 있습니다.
- 답변은 사이트 내 `내 문의`에서 확인합니다. 이메일 알림·첨부파일·대화 스레드·개별 문의 삭제 기능은 이번 범위에 포함하지 않습니다. 계정 영구 삭제 시 해당 계정의 문의도 함께 삭제됩니다.

## 저장·권한·오류 처리

- `public.support_inquiries`의 RLS는 최신 로그인 세션과 본인 소유 또는 관리자 권한을 요구합니다. 일반 사용자의 직접 INSERT/UPDATE/DELETE 권한은 없습니다.
- 접수·목록·답변 RPC는 서버에서 다시 권한과 입력을 검사합니다. 공개 RPC는 SECURITY INVOKER이고, 필요한 권한 상승은 private 함수 안에서만 수행합니다. 클라이언트에 관리자 키를 넣지 않습니다.
- 접수는 계정별 잠금을 사용해 1분 1회·24시간 10회로 제한합니다. 동일한 요청 ID의 재시도는 기존 문의 ID를 반환하여 중복 접수를 방지합니다.
- 관리자 저장은 읽었던 `updated_at`과 비교해 다른 탭에서 수정한 답변을 덮어쓰지 않습니다. DB 시간의 마이크로초를 원문 그대로 전달합니다.
- 본문·답변은 HTML이 아닌 일반 텍스트로 출력합니다. 네트워크 오류 시 입력을 유지하며 SQL 내부 오류를 사용자에게 그대로 표시하지 않습니다.
- 계정 전환·늦은 목록 응답은 공유 훅에서 구분하며 이전 계정 문의가 새 계정 화면에 표시되지 않도록 합니다.

## 검증

- `npm run verify:inquiries`: 입력 범위·유형, 응답/페이지 크기, 오류 메시지, DB 시간 정밀도, 보호 라우트 검사.
- `npm run verify:roles`, 변경 파일 정적 검사, 운영 빌드 통과. 기존 대형 JS 청크 경고는 남아 있습니다.
- `supabase/tests/support_inquiries.sql`: 일반/Pro 접수, 소유자 RLS, 관리자 답변, 중복 재시도, 분·일 등록 제한, 동시 수정 충돌, 10/3 페이지, 상태 필터, 만료 세션·비로그인 차단 검사 통과.
- DB 테스트는 트랜잭션 안에서만 계정·문의·관리자 세션 대역을 만들고 전부 롤백합니다. 실제 로그인 토큰을 발급하지 않았고 테스트 후 저장된 문의·검증 계정은 0개였습니다.
- 실제 UI 컴포넌트와 검증 전용 API로 작성 실패 시 초안 보존 → 접수 → 관리자 확인 중 → 답변 완료 → 작성자 읽기 전용 답변 확인까지 검증했습니다. 태그 문자열이 HTML로 해석되지 않고 모바일에서도 가로 넘침이 없음을 확인했습니다.
- 보안 어드바이저에 새 경고는 없습니다. 기존 RLS 기본 거부 정보와 Google 전용 로그인에 무관한 비밀번호 보호 경고는 유지합니다. [RLS 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
