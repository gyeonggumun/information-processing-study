# 실기 문제 3회 추가 검수

2026-10-22. 이전 4단계 검수 이후 남아 있는 반복 정의·과도한 합성 계산을 다시 검토했다. 현재 일반 연습 601개와 C·Java·Python·SQL 각 210개, 총 1,441개가 대상이다.

## 1차: 출제 유형과 교체 필요성

기존에 확보한 2023년 1회~2026년 2회 복원 220문항(`restoredExamsSource.json`)의 문제·코드를 대조했다. 이 자료는 비공식 복원이며 미래 출제를 예측하는 자료가 아니다. 근거가 적다는 이유만으로 모든 기초 개념을 없애지 않고, 반복 정의와 과도한 추가 연산 때문에 실전 연습 효율이 낮은 문항을 선정했다.

| --- | ---: | --- | --- |

## 2차: 독립적인 창작·정답 검산

- 복원 문항과 동일한 지문·코드를 사용하지 않고 데이터, 조건, 관계, 순회 방식 또는 반환식을 변경했다.
- 새로운 필답형 계산은 테스트에서 별도로 계산했다. 실행문 합집합, 조건·분기 결과 수, 독립 조건 쌍, 후보키 최소성, 관계대수 집합, RR·SJF·SRTF 시뮬레이션, LRU, 서브넷을 확인한다.
- SQL 집계와 CASCADE 동작은 외래키 검사를 켠 임시 메모리 SQLite에서 실행한다.
- 조건 커버리지는 단축 평가 여부, 스케줄링은 도착·실행 단위와 문맥 교환 및 동률 기준, 서브넷은 순번 기준을 명시했다. 이는 답을 유일하게 정하기 위한 조건이다.
- C·Java·Python은 실제 컴파일/실행 결과로 검증한다. C는 최적화 전·후 모두 검사한다. 새 코드 해설은 최소 5단계이며 계산 중간값과 코드 주석의 대응을 확인한다.

## 3차: 출제·해설·기존 기록 연결

새 문제에는 `-r5` ID와 `suitabilityRevisionOf`를 부여했다. 기존 ID는 무작위 출제 대상에서 제외하고 이전 문제 목록으로 옮긴다. 따라서 사용자의 풀이 내역과 오답노트는 당시 풀었던 원래 문제를 계속 보여 주며, 바뀐 문제의 정답으로 과거 기록을 재해석하지 않는다. 실기 복원 원문 페이지도 변경하지 않는다.

현재 문제 수는 그대로 유지된다. 기존 오답의 재풀이, 새 문제의 미풀이 판정, ID·본문 중복, 제출 전 해설 비노출과 제출 후 해설 렌더링을 검사한다.

검증 명령:

```text
npm run verify:practical-suitability
npm run verify:question-quality
npm run verify:practical-refresh
npm run verify:wrong-answers
npm run verify:python
npm run verify:java
node scripts/verify-c-questions.mjs node_modules/.cache/c-verifier/zig-x86_64-windows-0.15.2/zig.exe
npm run verify:detailed-solutions
npm run verify:question-presentation
npm run lint
npm run build
```

교체 목록은 `writtenSuitabilityAudit`와 `codeSuitabilityAudit`로 조회할 수 있다. 출제 가능성을 확정하거나 기존 모든 문제에 오류가 없다고 보장하는 검수는 아니다.
