## 현재 문제 은행과의 대조

- **기출 유형 연습(프로그래밍 제외):** 네 과목의 필답형 무작위 문제. 개념 판별·사례 적용은 충분하지만, 복원 자료에 반복되는 **표/절차를 실제로 계산하는 문제**의 비중이 낮았다. 이번에 관계 나눗셈·DISTINCT/NULL·UNION, 브로드캐스트 주소·서브넷 재분할, LRU 부재 횟수, 링크 비용 경로, RR 평균 대기시간, 테스트 기준 적용을 추가했다.
- **C:** 50문항×3난이도. 연산·배열·포인터·구조체·재귀·정렬·자료구조 출력 추적은 복원 문제의 주요 소재와 닮았다. 다만 빈칸에 코드를 써 넣는 형식은 없고, 상 난이도의 연결 리스트·함수 포인터 등은 복원 문제보다 복합적이다.
- **Java:** 50문항×3난이도. 상속·생성자·정적 필드·오버로딩/오버라이딩·인터페이스 출력 추적은 적합하다. 인터페이스 구현 키워드나 컴파일 오류 위치를 답하는 유형은 미구현이다. 배열 공변성·복합 정렬·그래프에 치우친 15문항은 아래 재대조에서 교체했다.
- **Python:** 50문항×3난이도. 슬라이싱·리스트 별칭·딕셔너리·함수·재귀 출력은 반복된 유형이다. 코드 빈칸 형식은 없다. 제너레이터·MRO·클로저 등 심화 훈련에 치우친 35문항은 아래 재대조에서 교체했다.
- **SQL:** 50문항×3난이도. 표와 쿼리를 함께 보여주고 결과/빈칸을 쓰는 형식, JOIN·GROUP BY·서브쿼리·UNION·LIKE·도메인 제약은 복원 문제와 가깝다. 2026-1회 유형을 반영해 외래키 제약문 키워드 빈칸 5개를 추가했고, 상대적으로 덜 직접적인 CASE 조건부 집계 5개를 교체했다. 복합 상관 서브쿼리는 유지한다.

## 해석과 남은 차이

### 2026-10-18 재대조 및 변형 96문항 적용

이번 요청에서는 지정된 11개 게시글(2023-1~2026-2)의 220문항과 일반 필답형 361문항·언어별 코드 150문항을 다시 비교했다. 아래 교체는 이 11회차 안에서 직접 확인한 개념에 가깝게 맞춘 것이며, 교체 전 주제가 시험 범위 밖이거나 다른 회차에 절대 출제되지 않는다는 뜻은 아니다. 기본 문법·개념 학습 문제는 유지했다. 별도 **실기 복원 페이지의 원문 220문항은 수정하지 않았다.**

모든 교체 문항에 `examReferences`로 비교한 실제 복원 문항 ID를 연결했다. 원문과 동일한 코드가 아니라 숫자·문자열·데이터·메서드 구조·조건을 바꾼 창작 변형이다. 이 근거는 같은 문제의 재현이나 동일한 난이도/출제 가능성을 보증하지 않는다. C의 함수 포인터처럼 실제 확인된 주제는 일괄 제거하지 않았다.

일반 필답형 총수와 C·Java·Python·SQL의 하·중·상 각 50문항은 유지한다. 내용이 달라진 문항에만 `-r2` ID를 부여하고 구버전은 `previousQuestions`를 통해 기존 풀이 기록·오답노트에서만 조회한다. 구버전을 풀었다고 새 변형까지 완료 처리하지 않으며 기존 계정 기록을 초기화하지 않는다. 과거 기록에서는 당시의 정답·해설이 유지된다.

검증: `npm run verify:exam-alignment`, 언어별 `verify:c`/`verify:java`/`verify:python`/`verify:sql`, 기존 기록·오답·복원 회귀 검사. 비교에 사용한 게시글 링크는 위 표 및 각 원본 복원 데이터의 출처에 보존한다. 언어 의미는 [Python 자료구조](https://docs.python.org/3/tutorial/datastructures.html), [Java 메서드 재정의·숨김](https://docs.oracle.com/javase/tutorial/java/IandI/override.html), [PostgreSQL 테이블 식](https://www.postgresql.org/docs/current/queries-table-expressions.html)도 참고했다.

모든 문제를 실제 기출과 일대일 대응시킨 것은 아니다. 복원 자료는 회차마다 약 20문항이고, 현재 코드 연습은 언어별 150문항의 **개념 변형 문제**다. 따라서 출제 가능성의 보증이나 공식 기출 재현으로 보아서는 안 된다. 특히 C·Java·Python의 빈칸 완성/오류 찾기에는 출력값 채점과 별도의 답안·검증 모델이 필요하므로 이번에는 출력 문제를 억지로 빈칸형으로 바꾸지 않았다. 향후 추가 시 독립 유형으로 구현·컴파일/실행 검증하는 것이 안전하다.
