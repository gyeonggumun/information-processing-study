## 범위와 기준

기존 일반 기출 521개와 C·Java·Python·SQL 각 190개, 총 1,281개를 대상으로 유형을 점검했다. 대조 자료는 저장소의 `restoredExamsSource.json`에 보존된 2023년 1회~2026년 2회 복원 11회분(220개)이다. 복원 자료는 공식 공개 원문이나 향후 출제 보장이 아니며, 자료에 없는 주제를 시험 범위 밖이라고 단정하지 않는다.

참고 페이지: [2026년 2회](https://chobopark.tistory.com/562), [2026년 1회](https://chobopark.tistory.com/561), [2025년 3회](https://chobopark.tistory.com/558), [2025년 2회](https://chobopark.tistory.com/554), [2025년 1회](https://chobopark.tistory.com/540), [2024년 3회](https://chobopark.tistory.com/495), [2024년 2회](https://chobopark.tistory.com/483), [2024년 1회](https://chobopark.tistory.com/476), [2023년 3회](https://chobopark.tistory.com/453), [2023년 2회](https://chobopark.tistory.com/420), [2023년 1회](https://chobopark.tistory.com/372).

교체 기준은 다음과 같다.

- 핵심 연산보다 무관한 상태 변경과 여러 기법의 중첩으로 길어진 문항을 축소한다.
- 자료에서 반복 확인된 식별·비교·빈칸·실행 결과·표 계산 유형을 우선한다.
- 출제 범위에는 들어갈 수 있어도 이 복원 자료와 연결이 약한 일반론은 반복 확인된 주제로 교체한다.
- 정상적인 기초 문법·알고리즘 문항은 자료에 같은 문법이 없다는 이유만으로 제거하지 않는다.
- 복원 문제를 그대로 복사하지 않고 사례, 표, 값, 연산을 새로 구성한다. VIEW 집계처럼 결합한 확장 유형은 `referenceBasis`로 명시한다.

## 교체 내용

- 일반 기출: 이해관계자·타당성·ATAM, CMMI·패키징·일반 EAI, 백업·IPC·RAID 식별 반복분을 패턴·응집도/결합도·테스트·관계형 용어·통신 보안 문항으로 보강했다. 이 주제들이 출제 불가능하거나 틀린 개념이라는 의미는 아니다.
- C: 트리 값 변경과 선택 카운터, 리스트 필터/역전/가중합, 행 포인터 순환과 재귀, 문자열 이중 별칭 재배치, 구조체 콜백 복합 문제를 문자열 주소·구조체 값/주소 복사·재귀 반환·이차원 배열 주소 추적으로 정리했다.
- Java: StringBuilder 편집·별칭, Deque API, 인터페이스 default의 특수 호출 문항을 문자열 비교·상속 필드/메서드·예외·재정의 재귀 유형으로 교체했다. 실제 복원에서 확인되는 제네릭 오버로드나 생성자 호출 등은 유지했다.
- Python: 가변 기본인자, 복합 가변인자, 메모 캐시 적중 수, finally의 반환 덮어쓰기, enumerate/zip·별표 언패킹 의존 문항을 슬라이싱·리스트 별칭/복사·문자열 분리와 정수 변환·클래스 딕셔너리 공유 유형으로 교체했다.
- SQL: 복원에서 관계대수로 제시된 디비전을 SQL 이중 부정으로 과도하게 확장한 문제, 조인·그룹별 평균을 겹친 일부 문제를 VIEW 집계·JOIN/GROUP BY/HAVING 표 계산으로 정리했다. 일반 기출에는 실제 R÷S 표 계산 문항을 추가해 디비전 학습을 유지했다.

추가 160개에는 패턴·UML·응집도/결합도, 동치 분할·경계값·커버리지, 관계형 용어·정규화·무결성·관계대수, 보안·서브넷·스케줄링 계산, 언어별 코드·SQL 표 계산이 포함된다. SQL은 입력값뿐 아니라 비교 기준도 달라져 선택 행 수와 결과가 달라진다.

## 데이터와 검증

- `practicalRefreshCode.js`, `practicalRefreshWritten.js`가 최종 출제 목록을 구성하고 `studyData.js`가 이를 사용한다. 기존 데이터 파일은 이전 버전 보존·회귀 검증의 기반으로 남겨 두었다.
- 교체 문항은 `기존ID-r3`와 `alignmentRevisionOf`로 연결한다. 교체 전 문제는 랜덤 목록에서 제외하고 기존 풀이/오답 복습 목록에만 보존한다. 사용자 저장 기록을 초기화하거나 삭제하지 않는다.
- 교체 내역 전체는 `codeRefreshAudit`, `writtenRefreshAudit`에 이전/이후 ID·유형·근거 ID로 남긴다. 추가분은 `practical-extra-` 접두사로 구분한다.
- `verify:practical-refresh`: 8항목별 추가 수, 현재/보관 ID, 중복, 근거 ID, 주석 위치, 실제 페이지 연결, 이전 오답과 풀이 연결을 검사한다.
- C는 컴파일 최적화 2종, Java는 컴파일·실행, Python은 실행, SQL은 인메모리 DB로 최종 출제 문제의 정답을 대조한다.
- SQL 해설 표 생성/검증은 최종 출제 목록과 보관분 모두를 사용한다. JOIN·WHERE·VIEW·그룹·최종 결과 표를 보존한다.
- 문제 제시 검증과 상세 풀이 검증도 최종 목록을 사용한다. 정답·오답 모두 제출 후에만 해설을 표시한다.
