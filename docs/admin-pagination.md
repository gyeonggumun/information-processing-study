# 관리자 계정 목록과 권한별 집계

- 한 페이지에는 최대 10개 계정만 표시합니다. 아래의 `이전`·`다음` 버튼으로 이동하고 현재 페이지를 표시합니다. 첫 페이지의 이전, 마지막 페이지의 다음 버튼은 비활성화합니다.
- 상단에 전체 계정·User·Pro·Admin 인원을 표시합니다. 검색 결과 수가 아니라 전체 가입 계정을 기준으로 한 현재 인원이며 별도 이력 통계는 아닙니다.
- 검색을 제출하면 첫 페이지부터 조회합니다. 권한을 변경하거나 계정을 삭제하면 서버 목록과 집계를 다시 불러옵니다. 마지막 페이지가 삭제로 비면 이전 페이지로 복귀합니다.
- `get_managed_users_page` RPC는 정렬 기준 `(created_at, user_id)`의 커서로 조회하고 11번째 레코드는 다음 페이지 존재 여부에만 사용합니다. 목록 10개와 전체 집계를 같은 서버 조회 결과로 제공합니다.
- 기존 관리자·최신 세션 검사를 그대로 적용합니다. User·Pro·비로그인 사용자는 계정 목록과 집계를 조회할 수 없습니다. 기존 목록 RPC는 이전 클라이언트를 위해 유지합니다.
- 서버 조회가 실패하면 인원을 0으로 오인 표시하지 않고 미확인 표시와 재조회 버튼을 제공합니다. 새로운 환경 변수·의존성·계정 권한 변경은 없습니다.

## 검증

- `npm run verify:admin-pagination`: 최대 10개, 마지막/빈 페이지, 커서 이력, 잘못된 응답·집계 거부 검사.
- `supabase/tests/admin_pagination.sql`: 23개 임시 계정의 10/10/3 분할, 같은 가입 시각의 ID 정렬, 중복·누락 방지, 검색 독립 집계, 권한 변경·삭제 집계, User/Pro/비로그인 차단 검사. 테스트 변경은 모두 롤백합니다.
- 실제 컴포넌트와 테스트 전용 API를 사용하는 화면에서 21개 계정의 10/10/1 이동, 이전 이동, 검색 초기화, 검색 결과 없음, 오류 안내, 권한별 인원 갱신, 마지막 1개 삭제 후 이전 페이지 복귀를 확인했습니다. 실제 계정은 변경하지 않았습니다.
- 모바일 390px 환경에서 집계 2열 배치와 가로 넘침 없음, 버튼 표시를 확인했습니다. 변경 파일 정적 검사와 운영 빌드 통과.
- 보안 어드바이저에 새 경고는 없으며 기존 private 테이블의 의도된 RLS 기본 거부 정보와 Google 전용 로그인에 무관한 비밀번호 보호 경고는 이전과 같습니다. [RLS 정보](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
