# 실기 복원 코드 상세 해설

## 변경 범위

- 복원 220문항 중 코드 관련 108문항: C 42, Java 35, Python 15, SQL 16.
- 이론·일반 계산 문제, 원문 문제 블록, 문항 ID, 정답·풀이 기록은 변경하지 않는다.
- 문항마다 3~7단계의 개별 설명, 총 548개 주석을 해당 코드 위치에 연결한다.
- 정답 공개 뒤 `풀이 핵심 → 주석 코드 → 코드 위치별 풀이 → 혼동 방지`를 표시한다.
- 기존 풀이 기록·오답노트도 동일한 패널을 사용하므로 보강 해설을 함께 볼 수 있다. 열람만으로 기록을 수정하지 않는다.
- SQL은 이미지·본문에 있던 문장을 코드로 전사하고, 필요한 문항에 조인 완성 표·행별 조건 표·집계 표를 추가했다.

## 원문과 학습용 코드 구별

원본은 `restoredExamsSource.json` 그대로 보존한다. 정답을 채운 코드, 누락 헤더·따옴표·예약어 오타를 보정한 코드에는 별도 안내를 붙인다. 출력형과 빈칸형의 요구 답안도 구분한다.

- Java static 오류 찾기: 오류를 고쳐 없애지 않고 원문 7행이 왜 컴파일 오류인지 설명한다. 주석 추가 뒤의 줄 번호를 답으로 사용하지 않는다.
- C 제어 흐름도: 입력과 배열 범위가 없는 위험한 `||` 코드를 임의로 실행 가능한 예제라고 취급하지 않는다.
- Python set 출력: 원소 순서를 보장하지 않으므로 동일 집합 여부로 검증한다.
- SQL 도메인 CHECK: 해당 문법을 지원하는 DBMS 기준임을 안내한다. NULL 금지를 자동 추론하지 않는다.
- 2024년 2회 SQL 빈칸: 원문 스키마와 열 목록 불일치를 안내한다. 정상 실행 SQL이라고 보장하지 않는다.

## 확인 방법과 결과

```powershell
npm run verify:restored-walkthroughs
node --experimental-sqlite scripts/verify-restored-walkthroughs.mjs --execute
node scripts/verify-restored-exams.mjs
```

- 주석 위치·누락 여부·보정 안내·원본 보존 검증.
- C 41문항을 O0/O2에서, Java 34문항을 컴파일·실행하고 기대 출력과 비교. C 흐름도 1문항은 별도 검토, Java 오류 찾기 1문항은 의도한 컴파일 실패 원인 검증.
- Python 15문항을 입력·집합 문제까지 실행 검증.
- SQL 14문항은 원문 표를 재현한 메모리 SQLite에서 실제 실행. 도메인 문법·원문 스키마 불일치 2문항은 별도 구분.
- 제출 전 해설 비공개, Pro 복습에서 해설 표시, 일반 User 접근 차단 검증.
- 기존 상세 코드 해설·문제 힌트 비노출·실기 유사 문제 회귀 검사 통과.
- 390px 모바일에서 C·Java·Python·SQL·오류 찾기 화면의 페이지 가로 넘침 없음. 긴 주석은 줄바꿈하며 문법 코드는 원문 구성을 유지한다.

실행 검증은 격리된 테스트 프로그램·메모리 DB에서 수행한다. 실제 사용자 계정·문제풀이 기록·서비스 DB는 수정하지 않는다.
