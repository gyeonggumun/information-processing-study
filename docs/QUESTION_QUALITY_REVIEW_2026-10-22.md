# 문제 품질 4차 점검

## 결과

- 불필요한 일반 비교 문항 21개와 복원 유형 대비 부가 처리가 많거나 특수 규칙에 치우친 코드 10개를 출제에서 제외하고 새 실기형 문항 31개로 교체했다.
- 일반 기출은 601개, C·Java·Python·SQL은 각각 210개로 총 1,441개를 유지한다. 복원 원문 220개는 별도이며 임의의 창작 문제로 대체하지 않았다.
- 제외한 31개는 기록·오답 복습 전용으로 보존한다. 이전 ID에 `-r4`를 붙인 새 ID와 `qualityRevisionOf`로 연결하므로 이전 답안과 새 문제를 섞지 않는다. 사용자 기록 삭제나 초기화는 하지 않는다.

## 1차: 유형 적합성

일반 문항 생성기의 비교형 지문 중 운영체제와 보안 용어, 스키마와 트랜잭션 등 직접적인 비교 의미가 약하고 기존 정의를 반복한 문항을 골랐다. 각 개념의 정상적인 기본 문항을 일괄 삭제하지 않고 반복 비교분을 교체했다.

| 범위 | 제외·대체 수 | 새 문항 내용 |
| --- | ---: | --- |
| 소프트웨어 설계 | 4 | 논리적·시간적 응집도, 제어 결합도, UML 연관 |
| 소프트웨어 개발 | 6 | 중위 순회, 체이닝, 분기 커버리지 계산, 드라이버·스텁 대응, 음수 경계값, 선택 정렬 |
| 데이터베이스 구축 | 7 | 복합 프로젝션, 내부 스키마, 자연 조인, DELETE·SET 빈칸, 현재 최고 정규형 판정, WHERE·HAVING 계산 |
| 정보시스템 구축관리 | 4 | NAT, 대칭·비대칭 암호 분류, IPsec, IaaS |

| Java | 5 | 생성자 순서, 부모·자식 필드, static 누적과 재정의. finally 반환 덮어쓰기 대신 복원에서 확인된 생성자 유형 |

근거 ID와 교체 전후 ID는 `questionQualityRevisions.js` 및 최종 목록의 `writtenQualityAudit`, `codeQualityAudit`에 보존한다. 근거 문제와 같은 문장을 복사하지 않았고 체이닝·응집도 세부 사례 등은 확인한 핵심 개념의 확장 유형이다.

## 2차: 정확성

- BCNF 정의의 ‘모든 결정자가 후보키’라는 부정확한 제한을 비자명 함수 종속의 슈퍼키 조건으로 통일했다. 2NF·3NF 설명도 후보키·비주요/주요 속성을 구분했다. [대학 데이터베이스 강의 자료](https://pld.cs.luc.edu/database/normalization.html).
- 외래키의 자기 참조·참조 가능한 유일키, 별도 NULL 제약을 구분하고 기본키의 대표 선택 조건을 명시했다. 카디널리티의 행 수와 ER 관계 비율을 한 정의로 혼합하지 않도록 했다. [PostgreSQL 제약조건 문서](https://www.postgresql.org/docs/current/ddl-constraints.html).
- 도메인 빈칸의 불필요한 괄호를 제거해 `INTEGER CHECK (조건)`으로 완성되도록 했다. [CREATE DOMAIN 공식 문법](https://www.postgresql.org/docs/current/sql-createdomain.html).
- SQL 키워드를 묻는 문항에서 잘못된 `REFERENCE`, 실제 키워드가 아닌 `Descending`을 정답 별칭에서 제외했다. LIKE 빈칸은 작은따옴표가 지문에 포함된 패턴 입력으로 통일했다.
- 경계값은 정수 입력임을 명시했다. RR의 도착·선점 큐 순서, 시간 단위, 문맥 교환 비용과 소수 반올림 조건을 보완했다.
- C의 `%X` 출력 인수를 `unsigned int`로 명시적으로 변환했다. 정답 출력값은 변하지 않는다.

## 3차: 중복과 기록

최종 1,441개에서 일반 지문과 코드·SQL 표의 완전 중복, 현재/보관 ID 충돌을 검사한다. 이전 오답은 보관 문제에 연결되고 새 문제는 새로운 출제 대상으로 남는지 메모리 기반 테스트로 확인한다. 문제 수와 기존 정답 기록은 유지한다.

## 4차: 실행과 채점

기존 필답형 채점은 소수점·음수·분수의 구분자와 숫자 사이 공백을 모두 제거했다. 따라서 `1.33`과 `13.3`, `-1.33`, `133`, `4 2`와 `42`, 일부 서로 다른 IP 주소가 같다고 판정될 수 있었다.

숫자·분수·주소를 먼저 분리하여 구조를 보존하도록 수정했다. 일반 용어의 대소문자·띄어쓰기, 쉼표로 구분한 다중 답안, 전각 문자, 불필요한 소수점 뒤 0은 허용한다. 정답 별칭과 오채점 반례를 자동 검증한다.

검증 명령:

- `npm run verify:question-quality`: 1~4차 점검, 독립 계산·SQL 키워드 실행·채점 반례·기록 보존.
- `npm run verify:c`, `verify:java`, `verify:python`, `verify:sql`: 최종 목록의 실제 컴파일/실행 결과와 정답 비교. C는 별도 컴파일러 인수가 필요하다.
- `verify:question-presentation`, `verify:detailed-solutions`: 제출 전 비노출, 제출 후 해설과 주석, 보관 문항 복습.
- `verify:practical-refresh`, `verify:additional-questions`, `verify:exam-alignment`, `verify:wrong-answers`: 기존 추가·교체 작업과 풀이 연결의 회귀 검사.

복원 자료는 비공식 복원이며 네 차례 점검이 향후 출제나 무오류를 보장하는 것은 아니다. 특정 문항의 추가 제보가 있으면 해당 ID를 기준으로 재현·검증할 수 있다.
